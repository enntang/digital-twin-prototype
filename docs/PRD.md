> 來源：Notion「翰霖科技資訊 / 數位孿生規劃」，2026-10-19 同步（含 P07 追加）。以 Notion 版本為準。

**版本：** v0.1　**日期：** 2026/10/18　**狀態：** Draft／內部討論
**產品階段：** Concept Prototype
**主要使用者：** 跨據點高階決策者
**原型目的：** 產品概念展示、內部需求討論、操作流程驗證

## 1. 產品概述

### 1.1 產品背景
物流企業已使用 CCTV、WMS、TMS 及各類設備監控系統，但資料分散，管理者需跨系統查詢才能理解營運事件的完整影響。
本產品以 **Operational Digital Twin（營運數位雙生）** 為概念，整合跨據點營運資訊，從營運監控走向風險分析與決策支援。

本次 Prototype 展示流程：**預測風險 → 分析影響 → 比較策略 → 制定決策 → 追蹤成效**

### 1.2 產品目標
| 目標 | 說明 |
|---|---|
| 營運可視化 | 快速掌握跨據點營運狀況 |
| 風險預測 | 呈現潛在營運風險及其發生時間 |
| 影響分析 | 理解風險成因、影響範圍及相關證據 |
| 決策支援 | 提供多種改善方案及模擬結果 |
| 成效追蹤 | 呈現決策執行狀態及改善成果 |

### 1.3 Prototype 定位
以內部概念展示為主，重點在資訊架構、畫面配置與核心操作流程，不驗證 AI 模型準確度或系統整合。
- 使用模擬營運資料
- 以 2D 地圖取代 3D 場域模型（例外：P07 單一設備深入檢視使用簡化 3D 設備模型，見 4.7）
- AI Copilot 採預設情境與模擬回覆
- 策略模擬使用預先定義的結果
- 不串接真實設備、CCTV 或企業系統（P07 即時影像以示意圖代替）

## 2. 目標使用者

### 2.1 主要：跨據點高階決策者
管理全國多個物流中心。關注：跨據點績效、出貨準時率與延遲風險、產能利用率、風險時間與影響範圍、策略成本效益、決策執行與成果。

> 在重大營運問題發生之前，辨識潛在風險，透過有依據的分析與策略比較，及時制定預防性決策。

### 2.2 次要
現場營運與維護人員、揀貨員、單一廠區主管——不在本次範圍，僅以模擬資料呈現其事件與執行結果。

## 3. 核心情境
系統預測未來七天內，北部物流中心可能因訂單量增加及分揀產能接近上限而出貨延遲。決策者需理解成因、評估影響、比較預防方案。

| 步驟 | 使用者行為 | 系統回應 |
|---|---|---|
| 01 | 查看全國營運總覽 | 顯示各據點指標與風險洞察 |
| 02 | 選取高風險事件 | 進入風險預測 |
| 03 | 查看風險分析 | 展開風險分析 Panel |
| 04 | 檢視 AI 建議方案 | 顯示方案 A、B、C |
| 05 | 選擇方案 | 進入策略模擬，保留已選方案 |
| 06 | 調整策略參數 | 更新模擬設定 |
| 07 | 執行情境模擬 | 顯示 Before / After 比較 |
| 08 | 確認採用方案 | 建立模擬決策紀錄 |
| 09 | 查看成效追蹤 | 顯示執行進度與預測／實際結果 |

**支線（追加）：** 步驟 03 中，若風險歸因指向特定分揀機（例：分揀機 A3 異常停機），決策者可點選該設備進入 **P07 設備深入檢視**，以 3D 模型與詳細資訊面板確認設備實況，再返回 P03 繼續步驟 04。

## 4. 功能需求

| 編號 | 畫面 | 主要資訊 | 核心互動 |
|---|---|---|---|
| P01 | 營運總覽 Dashboard | KPI、2D 據點地圖、AI 洞察 | 選據點或風險，進入預測 |
| P02 | 風險預測 Risk Intelligence | 風險指標、預測圖表、Risk Matrix、三張方案卡 | 選風險、展開分析、選方案 |
| P03 | 風險分析 Panel | 成因、關聯圖、資料證據 | 展開／收合 |
| P04 | 策略情境模擬 | 2D 地圖、策略選擇、參數 | 切換方案、調參、執行模擬 |
| P05 | 策略比較 Results | Before／After 地圖、關鍵指標 | 比較、返回調整、確認方案 |
| P06 | 決策成效追蹤 | 方案摘要、執行時間軸、成效指標 | 查看狀態及成果 |
| P07 | 設備深入檢視（追加） | 分揀機 3D 即時狀態、設備詳細資訊面板 | 旋轉／縮放模型、點元件看細節、返回 P03 |

### 4.1 P01 營運總覽
- 配置：左 KPI／中 2D 據點地圖／右 AI 洞察與風險事件列表
- 支援全國→區域→據點→樓層層級切換概念（預設資料即可）
- 點地圖節點顯示據點摘要；點風險事件進入 P02；節點顏色反映風險狀態

### 4.2 P02 風險預測
- 配置：上 風險摘要 KPI／中左 預測圖表／中右 Risk Matrix／下 AI 方案 A、B、C
- 選風險後更新圖表與摘要；分析入口展開 P03；點方案卡進 P04 並帶入所選方案
- **A、B、C 是同一風險的不同處理方案，不是三個風險事件**

### 4.3 P03 風險分析 Panel
- 內容：風險摘要、Dependency Graph、Evidence Panel（設備事件、WMS、紀錄）、營運影響摘要
- 從右側展開、可關閉返回、保留 P02 上下文、不另開完整頁面

### 4.4 P04 策略情境模擬
- 配置：左 2D 地圖與調度路線／右 策略設定 Panel
- 預設帶入上一步方案；可切換 A、B、C；每方案 1–3 個參數；「執行情境模擬」切到 P05
- 結果為預設情境資料，無真實最佳化

### 4.5 P05 策略比較
- 配置：左 Before 地圖／右 After 地圖／少量關鍵指標
- 同地圖範圍與比例；以顏色呈現路線或據點變化；策略 Panel 預設收合
- 可返回調整、可確認方案進 P06

### 4.6 P06 決策成效追蹤
- 配置：上左 方案摘要／上右 執行時間軸／下 成效分析
- 顯示核准狀態、負責單位、預計完成時間、執行紀錄、預測 vs 實際
- 全為模擬資料，需明確標示為示範情境

### 4.7 P07 設備深入檢視（追加需求）

> 2026-10-19 追加。當風險歸因指向特定分揀機時，決策者需要能深入確認該設備的實際狀況，判斷「這台機器現在到底怎麼了、多嚴重、會不會好」，再回到方案決策。

#### 4.7.1 目的與使用情境
- 對象仍是高階決策者：重點是**確認歸因是否可信、嚴重程度、預計影響時間**，不是維修操作。
- 情境範例：P03 顯示「分揀產能下降」主因為「分揀機 A3 異常停機（E21）」與「分揀機 A1 降速 60%」→ 點 A3 → 看到 3D 模型中掃描門架後的第 3 分流模組停擺、標示 E21，面板顯示停機時間、影響處理量、保養逾期 → 決策者確認方案 C（提前設備保養）合理 → 返回 P03／P02 選方案。

#### 4.7.2 進入點與返回
| 進入點 | 觸發 | 帶入設備 |
|---|---|---|
| P03 Dependency Graph | 點選設備類成因節點（如「分揀機 A3 異常停機」） | 對應設備 |
| P03 Evidence Panel | 點選來源為「設備」的證據項目，項目右側顯示「檢視設備 →」 | 對應設備，並在事件時間軸定位該筆 |
| P01 樓層平面圖（FloorPlan） | 點選狀態為 alert／down 的分揀機區塊 | 對應設備 |

- 呈現方式：全畫面覆蓋層（Overlay），蓋在原頁面之上，**保留原頁面狀態**（P02 已選風險、P03 展開狀態不變）。
- 返回：左上「← 返回風險分析」（依來源顯示對應文字）／Esc 鍵，回到進入前的畫面與狀態。
- 網址帶參數（如 `?equipment=tpe-a3`），重新整理或瀏覽器返回皆可正確開關。
- 頂部可切換同據點其他分揀機（A1／A2／A3 分頁），預設為進入點指定的設備。

#### 4.7.3 版面配置
- **左 約 65%：3D 設備檢視區**　**右 約 35%：設備詳細資訊面板**（可捲動）
- 頂列：麵包屑（據點 › 樓層 › 分揀機 A3）、設備狀態標籤、「模擬即時資料」標示、最後更新時間。

#### 4.7.4 3D 設備檢視區
**模型結構**（參考使用者提供之分揀線示意圖 [sorter-model](reference/sorter-model.png)，以簡化幾何體程序生成，不需 CAD 精模）：

| 元件 | 說明 | 狀態可視化 |
|---|---|---|
| 入口輸送段 | 平皮帶輸送機＋鋼構支架 | 皮帶流動速度 |
| 掃描門架（Scan Tunnel） | 條碼／尺寸掃描，位於主線末端門架 | 讀取率異常時門架燈號變色 |
| 主線皮帶段 ×4 | 分段平皮帶，各段獨立驅動馬達 | 速度、馬達溫度 |
| 分流模組 ×4 | 擺輪／滾輪分流區（藍色模組） | 動作中／停擺／異常 |
| 出口滑道 ×4 | 弧形滾筒輸送道，各對應一個出貨道口 | 堆積量（包裹數量） |
| 驅動馬達／軸承 | 以小型元件附掛於各段下方 | 溫度、振動 |

**即時狀態呈現（模擬）**
- 包裹以小方塊沿輸送線移動，速度依設備當下處理量比例；**停機段包裹停止並堆積**，降速段明顯變慢。
- 元件依狀態著色，與全站狀態色一致：正常（冷色基底）／注意（黃）／警示（橘）／停機（紅，脈動閃爍）。
- 異常元件上方顯示浮動標籤（例：「E21 停機」「馬達 85°C」），標籤數量 ≤ 3，避免遮擋。
- 選填：溫度熱度覆蓋層開關（Heat overlay），以色階顯示各段溫度。

**互動**
- 滑鼠拖曳旋轉、滾輪縮放、右鍵平移；「重設視角」按鈕。
- 預設視角：等角斜俯視整條線（同示意圖角度），並自動對焦到異常元件。
- Hover 元件：tooltip 顯示名稱＋1–2 項關鍵數值。
- 點選元件：元件高亮、鏡頭平滑移至該元件，右側面板切換到該元件細節；點空白處取消選取。
- 右側面板點元件列表項目，3D 同步高亮（雙向連動）。

#### 4.7.5 設備詳細資訊面板
由上而下：
1. **設備摘要**：名稱、編號、所屬據點／區域、目前狀態、狀態持續時間（例：停機 38 分鐘）、對應風險事件（連回 P02 該風險）。
2. **即時影像**（2026-10-19 追加）：連結該設備的 CCTV 即時畫面，讓決策者以實際影像佐證 3D 與數據的判讀。
   - 預設 2 路鏡頭：「主線近景」（鏡頭編號 `CAM-{設備編號}-01`，對準輸送主線與分流段）、「分揀區全景」（`CAM-{據點}-SRT`，俯瞰整個分揀區）。
   - 面板內以 16:9 縮圖並排；畫面疊加 LIVE 紅點、鏡頭編號、時間戳記（隨模擬時間跳動）、鏡頭名稱。
   - 點擊縮圖：影像放大覆蓋左側 3D 區，可在鏡頭間切換；「返回 3D 檢視」或 Esc 收合（Esc 先收合影像，再按一次才關閉 P07）。右側面板保留，可對照數據。
   - Prototype 以靜態示意圖代替串流，畫面須標示「示意影像」：[cctv-01](reference/cctv-01.jpg) 主線近景、[cctv-02](reference/cctv-02.jpg) 分揀區全景。
3. **即時指標**（每 2–3 秒以模擬資料小幅跳動，含迷你趨勢線 Sparkline）：
   - 處理量（件／小時，對比額定值）
   - 輸送帶速度（m/s）
   - 馬達溫度（°C，標正常範圍 0–70）
   - 振動值（mm/s，標警戒 7.1）
   - 供電電壓（V）
   - 分揀錯誤率（%）
   超出正常範圍的數值以警示色標示。
4. **元件健康狀態列表**：依 4.7.4 元件逐列，顯示狀態燈與主要異常說明；點選與 3D 連動。
5. **事件時間軸**：此設備相關事件（設備告警、錯誤碼、電力事件、WMS 影響），**與 P03 Evidence 同一份資料**，由新到舊。
6. **維護資訊**：上次保養日、預定保養日、是否逾期（天數）、近 30 天停機次數。
7. **對營運的影響**：此設備異常造成的產能損失（%）、受影響訂單數、隊列等候時間；並提示「相關處理方案：方案 C 提前設備保養」，點擊後返回 P02 並選取該方案。
8. （選填）**近期預測**：沿用 P02 趨勢圖樣式，顯示此設備關鍵指標未來 3–7 天預測與警戒線。

#### 4.7.6 示範資料（須與現有 P01–P03 資料一致）
| 設備 | 據點 | 狀態 | 關鍵異常 | 關聯風險 |
|---|---|---|---|---|
| 分揀機 A3 | 台北 A | 停機 | Error Code E21、14:28 自動停機 | 台北 A 出貨延遲風險 |
| 分揀機 A1 | 台北 A | 警示 | 降速 60%、馬達溫度 85°C、電壓 210V→185V | 台北 A 出貨延遲風險 |
| 分揀機 A2 | 台北 A | 正常 | — | — |
| Sorter B（分揀機 A2 區） | 台中 C | 警示 | 振動 4.9 mm/s（+53%）、軸承 68°C、錯誤率 0.4%→1.1%、保養逾期 12 天 | 台中物流中心設備故障風險 |

#### 4.7.7 AI Copilot
本畫面預設問答，例：
- 「分揀機 A3 為什麼停機？多久能恢復？」
- 「這台設備對本週出貨的影響有多大？」
- 「提前保養能解決這個問題嗎？」

## 5. 共用元件與設計規範

### 5.1 AI Copilot（跨畫面）
依畫面提供不同預設問答，例：
- 風險預測：「為什麼北部物流中心的延遲風險升高？」
- 策略模擬：「哪個方案最能降低出貨延遲？」
- 成效追蹤：「目前的改善結果是否符合預期？」

不串接 LLM。

### 5.2 資訊呈現原則
以手繪 Wireframe 為版面依據；避免資訊過載；漸進式揭露；保留地圖與圖表空間；次要資訊用 Panel；不為填版面加 KPI。

### 5.3 視覺化規範
2D 地圖與簡化圖形；地圖支援據點狀態、選取、路線高亮、策略比較變化。不做 3D 倉庫模型。
- 例外：P07 允許**單一設備**的簡化 3D 模型（程序生成幾何體），沿用暗色戰情室風格與全站狀態色；不擴及整棟倉庫或場域。

## 6. 非功能需求

| 項目 | 規格 |
|---|---|
| 平台 | 桌面版 Web Prototype |
| 建議技術 | React、TypeScript、Vite |
| 資料 | Mock Data |
| API | 不需串接 |
| AI | 預設回覆與模擬分析 |
| 3D | 僅 P07 單一設備模型；建議 three.js＋@react-three/fiber（＋drei），以 lazy load 分包，不影響其他頁面載入 |

| 儲存 | 前端狀態或 Local Storage |
| 權限 | 不實作 |
| 資料一致性 | 同一事件在各畫面使用一致資料 |

## 7. 驗收標準
1. 能從總覽進入指定風險事件
2. P02 呈現摘要、圖表、Risk Matrix 及三種方案
3. P03 可正常展開與收合
4. 點方案 A/B/C 後，P04 保留所選方案
5. 能調參並看到對應示範結果
6. Before／After 地圖有明確視覺差異
7. 能確認方案並進入 P06
8. Copilot 依當前畫面顯示對應內容
9. 流程可連續完成，無無效按鈕或無法返回的畫面
10. 版面符合手繪 Wireframe，不額外增加大量資訊區塊
11. （P07）可從 P03 成因節點、設備證據及 P01 平面圖進入對應設備的深入檢視
12. （P07）3D 模型可旋轉、縮放、重設視角，異常元件以顏色與標籤明確標示，停機段包裹停止流動
13. （P07）點 3D 元件與面板元件列表可雙向連動
14. （P07）面板數值、事件與 P03 Evidence 一致，並標示為模擬即時資料
15. （P07）返回後 P02／P03 狀態保留不變
16. （P07）面板可檢視 2 路示意即時影像，點擊可放大、切換鏡頭並返回 3D 檢視

## 8. Out of Scope
真實 AI 預測模型、What-if 最佳化演算法、3D 倉庫／場域模型／AR（P07 單一設備 3D 除外）、真實設備 CAD 模型匯入、設備遠端控制／維修工單操作、CCTV 串流（P07 僅以示意圖呈現）、WMS/TMS/WCS 串接、維修人員介面、揀貨 PDA 流程、登入與權限、工作流程引擎、跨裝置與電視牆適配。
